# RRBOX 使用说明

## 从订阅开始

进入“订阅 → 添加订阅”，填入 HTTP/HTTPS 地址和可选名称，点击“添加并同步”。也可在“节点 → ＋”从剪贴板、相机、图片或文本导入。带认证的根 HTTP 地址通常按代理节点处理；根订阅或带认证的资源地址有歧义时请选择“作为订阅”。失败不会创建空订阅组，输入框使用后自动清空。

主导入上限为 8 MiB、2048 个节点，Network Lab Raw 上限 256 个。订阅返回普通网页、无效格式或超限内容不会作为成功订阅保存。

## 选择、命名和编辑

展开节点组，点选节点，再到仪表盘连接。仅选择节点不会自动重启当前 VPN；当前运行中的本地节点受到删除保护。

“流量信息(勿选)”等明确的信息条目，在地址为回环 / 占位地址且端口为 9 时显示为流量概览，内容可换行查看和长按复制，不参与连接或测速。剩余、已用、总量和到期日期以订阅实际提供的文字为准；没有提供的字段不会补造，其他说明仍完整显示。真实服务器上名称带“流量”的普通节点不会因此被禁用。

右侧菜单“重命名”改变显示名字；“编辑节点”改变实际连接配置。“恢复订阅值”清除该订阅节点全部本地覆盖，包括自定义名称。刷新时只在能唯一匹配身份的情况下继承名称；若服务器、名称和认证同时变更或出现重复项，可能视为新节点，避免覆盖误配。

保存前检查配置；编辑正在使用的节点不会擅自打断当前连接。断开重连或下次使用快捷开关时采用最新参数。

订阅分组右侧菜单可“重命名分组”，在节点页和订阅页都能操作。名称为 1–80 个字符，仅更新分组显示名称；订阅地址、节点身份和连接设置不变。即使改名时订阅正在下载，更新内容也不会覆盖手动名称。

## 分享节点与订阅

单节点右侧菜单进入分享，可展示二维码、复制链接或调用系统分享。链接由当前有效节点参数生成，包含已保存的本地编辑。无法完整表示为通用链接的配置使用 JSON 文件，避免分享时悄悄丢失连接参数；流量信息条目不生成连接链接。

订阅分组菜单的分享使用订阅地址，二维码和复制链接对应同一个地址；分组显示名称不会写入或改动地址中的认证参数。接收者导入后自行下载订阅，不是只拿到当前选中的一个节点。

二维码容量有限，内容过长时请使用复制或保存文件。节点链接与订阅地址本身包含连接凭据，分享界面保留这些参数以便接收者导入；它们与自动脱敏的诊断日志不同。

二维码也可保存或分享为 PNG 图片。交互参考 [v2rayNG 的节点分享](https://github.com/2dust/v2rayNG/blob/2020807c255b76b09c9ced4255c95600250aef48/V2rayNG/app/src/main/java/com/v2ray/ang/handler/AngConfigManager.kt)和 [NekoBox 的链接 / 配置分享](https://github.com/MatsuriDayo/NekoBoxForAndroid/blob/5768494d8ae3c74a057bb6d46c0f8dc071b0d821/app/src/main/java/io/nekohasekai/sagernet/ui/ConfigurationFragment.kt)，在 RRBOX 现有菜单中独立实现。

Ping 是服务器 ICMP 延迟，不是完整代理协议测速。部分服务器禁用 ICMP，显示超时不必然说明代理节点不可用。测速时先断开 VPN，避免当前代理路径影响结果。

## 引擎和分流

默认 System，无需 Root；HEV 是可选 native 路径，不保证对每条线路更快。1.0.1 也提供可选 Root 高级模式，需要授予 RRBOX Root 权限，通过独立 TUN 和 UID 路由接管流量。出现兼容问题先回到 System。Root 的使用、清理和验证边界见 [Root 高级模式](ROOT-LAB.md)。

Network Lab 的 A/B 和恢复演练会重建或暂时停止数据面，测试期间已有连接可能中断，不应在重要通话 / 下载时运行；Root 运行期间暂停 System / HEV 的 A/B 演练。

HEV 使用 sing-box 返回真实 DNS 地址，停止生成重启后会失效的临时映射。HEV 的内部 DNS 服务始终可用；“智能 DNS”开关控制其他 DNS 流量是否接管，不会关闭 VPN 自身的解析器。首次从旧版升级后，其他应用可能仍缓存旧的 `100.64.*` 地址；如果个别应用卡住，请彻底关闭后重新打开，仍有残留可重启手机一次。程序无法可靠还原旧进程已丢失的映射，不会猜测或将运营商共享地址整段强制直连。

“应用接管范围”中的“所有应用”“仅选中应用”“选中绕过”互斥。仅选中应用模式至少选择一项；这决定哪些应用使用 RRBOX，不代表所有连接都走代理。开启设置中的“中国大陆智能分流”后，国内服务与局域网直连，其余业务使用当前代理节点。关闭智能分流后，接管范围内的业务连接全部使用代理。

在“仅选中应用”下点击“自动选择”，会匹配已安装的常用海外应用和谷歌服务，并保留手动添加、手动取消的选择。你仍可搜索应用或包名逐项调整；浏览器须按需手动勾选，浏览器登录 GPT 时也要将实际使用的浏览器加入名单。新装应用后再点一次会补充匹配项，已卸载项会清理，不会在后台自动改动名单。预装应用和推荐的谷歌服务也会显示。整批选择保存后只重新应用一次。

未选应用业务直接联网。Android 按 UID 接管，同 UID 的应用无法完全拆分；Root 为兼容系统共享解析器，物理 DNS 地址仍统一处理。名单为空时不会自动扩大到所有应用，请至少选择一项再连接。


智能分流补充了微信、国内抖音、支付购物、外卖出行、地图和常用视频等国内服务的离线域名规则。海外 TikTok 的 API、视频和直播域名优先走代理；第三方插件版即使更改应用包名，访问相同海外域名时也使用同一策略。微信内打开外部网站、短链接跳转后的目标、小程序自己的服务器分别按实际域名判断；不会因为来源是国内应用就把全部业务强制直连。

另外补充国内 AI、音乐阅读、银行政务、运营商认证和部分明确的智能家居端点；国际社交、开发平台及 Steam 商店/社区使用海外规则。浏览器、终端、远程桌面等混合用途应用仍按目标地址分流，多地区设备云的未知端点不根据应用名字猜测。

System 在 Android 10+ 且成功识别连接来源时、Root 在成功查询原连接 UID 时，对 TikTok 主客户端与已知独立插件、BIGO 等已审核海外应用增加精确包名代理保护，优先于国内域名和 IP 规则；已知私网地址不命中这条保护。国内抖音不在保护名单。HEV 或包名查询失败时仍依赖域名 / IP 规则；DNS 继续按域名选择，不能保证每条系统 DNS 查询都携带原应用身份。

微信 / 国内抖音 / TikTok 的重点场景和验证边界见 [智能分流验收](SMART-ROUTING-VALIDATION.md)。规则覆盖不代表每个插件版本、账号地区或运营商条件都已经实机验证。

设置中的“立即更新分流规则”统一更新中国域名 / IP 与自定义策略，显示自定义规则版本、规则包版本和启用状态。下载后先校验签名、版本及逐文件哈希，再暂存候选；应用成功后才确认启用，失败继续使用可用规则。需要切换运行配置时会短暂重连，建议空闲时更新。更新保持原节点和引擎，不会在用户断开后重新连接。

普通域名、包名和精确 IP 分类可通过该按钮更新。新的网络恢复逻辑、引擎或界面功能必须升级 APK；规则更新成功不表示客户端已经升级，也不代表全部业务已验证联网。

## X 与微信的地址恢复

X 的部分连接会沿用重连前缓存的公网地址。1.0.1 对规则允许的精确 X 服务域名，在可识别 HTTP / TLS / QUIC 时重新解析，保留端口和原有分流优先级；不猜测未知裸 IP，也不还原已经丢失的旧 HEV 合成地址映射。

微信兼容处理适用于 Android 13 及以上的 Root 模式：当前物理网络明确存在 IPv4 地址和默认路由，但缺少公网 IPv6 地址或默认路由时，符合当前直连策略的精确微信服务域名可进行 TCP 地址恢复。它不会全局关闭 IPv6；正常双栈、纯 IPv6、未知网络状态、旧版 Android 和 System / HEV 沿用原路径，微信 UDP 不被改写。判断依据本机网络快照，无法据此发现所有上游 IPv6 故障。

## 查看应用的连接流向

测试时关闭“轻量模式”，将“应用接管范围”设为“所有应用”，然后进入“Network Lab → 日志”查看连接流向。记录包含内核识别到的应用、目标域名 / IP、TCP / UDP 和实际出口，方便分别测试微信、国内抖音和插件版 TikTok。可按应用、目标或出口检索，再通过日志页复制 / 导出。

应用名称仅在实际获得来源身份时显示。HEV 转换后的本机 SOCKS 连接可能没有原始应用身份，这类连接显示“未知应用”，不会把 RRBOX 自己当成来源应用。被设为绕过或未选中接管的应用不经过 RRBOX，无法在这里观察。

详细日志区分路由观察和连接结束，附会话 / 连接标识以及核心提供的上传、下载累计字节。路由观察不代表握手成功，连接结束也不代表正常完成。固定核心接口没有提供的错误原因或最终解析 IP 会明确保留为未知；核心警告与错误另存为 CORE 通道，排查时选择“全部日志”。共享地址提示只表示需要核查，不等同于已确认旧映射。

日志页的保留设置默认 2000 条，可选择 600 / 2000 / 5000 / 10000 条、自定义 100–1000000 条，或“持续保留”。记录保存到手机本地，关闭界面或重开 RRBOX 后仍可查询。有限数量模式淘汰较早记录；调小数量会立即裁剪历史。“持续保留”不按条数自动清理，直到主动清空或更改保留设置，会持续占用存储空间。

搜索覆盖全部已保留历史，列表每页最多 200 条；可以翻页查看较早记录。排查引擎切换后的地址问题可搜索 `100.64.`，查看某个应用则输入包名，例如 `com.instagram.barcelona`；看到代理 / 直连表示选路结果，仍需结合实际访问和错误记录判断是否连接成功。

“导出 TXT”通过系统文件保存器写入完整匹配记录，包含时间、频道及脱敏内容，不受当前显示页限制。清空搜索并选择全部日志可导出全部历史；复制仅针对当前显示页，避免大量文本超过剪贴板大小。导出期间仍可继续采集。

打开轻量模式后会停止额外连接事件订阅与逐连接日志记录，保留必要错误与少量状态信息；已有历史仍能查看、导出。保留数量不会改变采集开关。日志按连接事件记录，不是逐包抓包；突发速度超过写入缓冲能力或存储失败时会明确提示，不能用“持续保留”推断每个连接都一定已被捕获。

## 证书错误

新版默认校验 HY2 / TUIC 的服务器证书。先核对服务器时间、域名、SNI 与证书信任链。确实使用自签证书且已确认服务器身份时，可在编辑页显式开启“跳过 TLS 证书校验（不安全）”；这会降低身份验证保护。Raw 模式以 JSON 字段为准，切勿为普通网络故障盲目关闭验证。

## JARVIS 助手直连

1.0.2 内置 `app.jarvis.assistant` 精确包名直连。覆盖安装后开启智能分流，断开并重新连接 RRBOX 即可；不需要另外填写包名。System / Root 能识别应用身份时，该应用的业务连接优先直连，包括它访问的其他服务。关闭智能分流后恢复默认代理行为。

`api.deepseek.com` 的连接和 DNS 也走直连，HEV 或包名无法识别时仍可使用这条域名策略。规则版本 `2026090803` 将 API 域名单独列出；旧规则已有的 `deepseek.com` 后缀同样覆盖它。包名能力需要升级 APK，仅点击规则更新不能让 1.0.1 获得该能力。

## 升级到 1.0.2

本版升级为 `1.0.2 / 102`，可从同签名的 1.0.0 / 1.0.1 覆盖安装。在 App 内检查更新，或打开 [正式 Release](https://github.com/Xiaowu7z/RR-BOX/releases/latest) 下载 `RRBOX-1.0.2-arm64-v8a.apk`。包名与正式签名保持一致，可直接覆盖安装并保留节点、订阅和设置，无需卸载；安装后重新连接 RRBOX。

App 内版本比较可识别这次升级，Obtainium 也可跟踪正式版。“立即更新分流规则”不能代替 APK 升级。需要核对具体构建时，查看 Release 的源码提交、构建报告与 APK SHA-256。

## 反馈问题

提供 Android 版本、机型、引擎、Wi-Fi / 蜂窝环境、协议类型、重现步骤和构建哈希；不要公开订阅链接、密码、UUID 或私钥。Network Lab 日志自动脱敏并不覆盖所有自定义字段，发送前请自己检查。涉及真实凭据先撤销 / 轮换，再提交不含敏感值的复现。
